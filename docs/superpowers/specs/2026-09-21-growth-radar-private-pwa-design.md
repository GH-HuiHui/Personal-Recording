# 成长雷达：iPhone 本地隐私 PWA 设计

## 决策

采用 `Framework7 iOS 风格 PWA + GitHub Pages + IndexedDB 本地存储 + 加密导出/导入`。

GitHub Pages 只托管公开的静态程序外壳。个人阶段、方向与行动记录不上传，不引入账号、数据库、分析 SDK 或后台接口。其他人打开同一网址时，只会得到一份独立的空白本地数据。

## 用户目标

- 在 iPhone 主屏幕像普通 App 一样打开。
- 一次点击完成记录，操作时间不超过 2 秒。
- 电脑关机后仍可使用。
- 页面离线可打开，记录离线可写入。
- 换机或 Safari 数据被清理前，可用加密文件备份与恢复。

## 范围

### 本次实现

- 保留现有“今天 / 历史 / 设置”三 Tab 和已确认的 Apple 风格视觉层级。
- 使用 Framework7 的 iOS 交互基础，但不机械套用默认主题；现有视觉稿继续作为视觉真值。
- 将每次 `+1` 保存为独立 ActionRecord，而不是只保存累计数字。
- 由 ActionRecord 实时聚合今日次数、近 7 日次数、活跃天数和阶段活跃率。
- 支持撤销最近一次记录。
- 支持安装清单、Service Worker、离线 App Shell 与安全缓存升级。
- 支持导出加密备份文件与导入恢复。
- 提供 GitHub Pages 的自动构建配置和 iPhone 添加主屏幕说明。

### 明确不做

- 账号、云同步、多人共享、服务端数据库。
- 将个人记录提交到 GitHub。
- 通知、AI 建议、积分、连续签到、社交功能。
- 以网址私密性代替数据隐私；网页外壳可以公开，个人数据保持设备本地。

## 架构

项目采用小模块结构，避免继续扩大单一 `app.js`：

```text
growth-radar-preview/
├── index.html
├── manifest.webmanifest
├── service-worker.js
├── styles/
│   ├── tokens.css
│   └── app.css
├── src/
│   ├── app.js
│   ├── data/
│   │   ├── db.js
│   │   ├── seed.js
│   │   └── backup.js
│   ├── domain/
│   │   └── analytics.js
│   └── ui/
│       ├── radar.js
│       ├── today.js
│       ├── history.js
│       └── settings.js
└── assets/
```

- `data` 只负责持久化、种子数据和备份。
- `domain` 只负责自然日统计，不依赖 DOM。
- `ui` 只负责渲染与交互，通过明确函数调用数据层。
- Service Worker 只缓存静态资源，不截获或上传个人数据。

## 数据模型

IndexedDB 使用三个对象仓库：

- `stages`：`id`、`name`、`createdAt`、`endedAt`、`status`。
- `dimensions`：`id`、`stageId`、`name`、`icon`、`sortOrder`、`isEnabled`。
- `records`：`id`、`stageId`、`dimensionId`、`createdAt`。

所有标识使用 UUID。日期保存为 ISO 8601 字符串；统计时按本机时区的自然日起点归一化。新阶段复制方向为新对象，旧阶段数据保持只读和隔离。

首次启动仅在数据库为空时创建阶段 1 与六个默认方向，不写入示例行动记录。

## 加密备份

- 用户在设置页输入备份密码后导出单一文件。
- 使用 Web Crypto：PBKDF2-SHA-256 派生密钥，AES-GCM 加密。
- 每次导出生成随机 salt 与 IV；文件仅包含版本、KDF 参数、salt、IV 和密文。
- 密码不保存、不上传；忘记密码无法恢复备份。
- 导入先完成格式校验与解密，再要求用户确认覆盖；失败时不修改现有数据库。
- 恢复采用事务写入，任何一步失败都整体回滚。

## PWA 与 GitHub Pages

- `manifest.webmanifest` 使用 `standalone`、中文名称、主题色和主屏幕图标。
- Service Worker 采用版本化 App Shell 缓存；激活新版本时清理旧缓存。
- 页面部署路径不得写死根目录，必须兼容 GitHub Pages 的仓库子路径。
- GitHub Actions 只构建并发布静态资源，不读取业务数据和密钥。
- 安全基线：无第三方分析、无远程字体、无动态远程脚本、无源码中的秘密；通过 CSP 限制资源来源。

## iPhone 交互

- 首屏保持大标题、分段控件、雷达图、方向列表与底部 Tab。
- `+1` 触控区域不小于 44×44 px；按下即时反馈，数字先更新，持久化失败再回滚并提示。
- iOS Safari 不保证网页振动，因此触觉反馈视为渐进增强，动画与视觉状态必须独立成立。
- 适配 `safe-area-inset-*`、动态视口、深色模式、减少动态效果与 VoiceOver 标签。
- 安装说明放在设置页，不在每次启动时弹窗干扰记录。

## 错误处理

- IndexedDB 不可用：显示阻断提示，并提供导入/导出之外的只读说明，不假装保存成功。
- Service Worker 更新失败：继续使用当前缓存版本，下次启动重试。
- 备份密码错误或文件损坏：保留现有数据并明确提示。
- 存储空间不足：回滚本次写入，提示用户立即导出备份。

## 验收

1. 首次启动得到阶段 1、六个方向、零条记录。
2. 点击阅读 `+1` 后刷新或关闭重开，计数仍为 1。
3. 同一天点击三次，次数为 3，雷达活跃天数仍为 1。
4. 撤销最近记录后，刷新仍保持撤销结果。
5. 断网重开主屏幕 PWA，首页和本地记录仍可用。
6. 导出加密文件、清空测试数据库、输入正确密码导入，数据完整恢复。
7. 错误密码导入失败且原数据不变。
8. GitHub Pages 子路径下资源、路由、图标与 Service Worker 正常。
9. 393×852 iPhone 视口无横向溢出，核心记录路径可单手完成。
10. 控制台无相关错误；视觉 QA 与原始截图比较后无 P0/P1/P2 差异。

## 风险与边界

- Safari 删除网站数据会删除 IndexedDB，因此加密备份是必要保护，不是可选同步。
- 该方案不会跨设备自动同步；恢复需要用户主动导入备份。
- GitHub Pages 网址和前端代码可被访问，但个人记录不会随页面发布。
